# v1.0.4 リファクタリング

## 方針

機能追加・仕様修正・依存ライブラリ更新とは分離し、重複した処理を共通化する。
Firestoreのクエリ、取得回数、認証の監視、キャッシュ更新、保存形式は変更しない。
`flutter_tutorial_overlay` の `finshText` と既存のバージョン固定を維持する。

## 変更と理由

| 領域 | 変更 | 理由 |
| --- | --- | --- |
| 起動 | `main.dart` / `main_dev.dart` から共通の `bootstrap` と `MyApp` を呼ぶ | 本番・開発で初期化処理が乖離するのを防ぐ。OAuthのIDは各エントリーポイントに残す |
| 初期データ | `loadInitialData` に既存の読み込み順を集約 | 参照データ→ユーザー→イベント・参加情報→カレンダーの依存関係をテストできる |
| イベント結合 | `EventDetailsMapper` にタグ・会場・グループとの結合を抽出 | 通信なしの純粋な変換として欠損・重複データをテストできる |
| 非同期処理 | 待機処理のない `async` + `Future.wait` を同期的な `map` に変更 | 不要なFuture生成を避け、実際に通信する非同期処理と区別する |
| 一覧 | 共通のフィルタ処理とソート比較を集約 | マイイベント・イベント選択・出力画面で検索条件が乖離するのを防ぐ |
| 状態更新 | キーワード変更を既存の設定更新メソッドへ委譲 | 同じ `copyWith` と再絞り込みの重複をなくす |
| 通知 | `EventNotificationPlan` に通知対象選択を抽出 | UI・保存・通知プラグインから切り離して選択ルールをテストできる |
| Dart記法 | `switch` 式、collection-if、`final` を利用 | 列挙型の分岐を網羅し、追加対象と不変のローカル値を明示する |
| CI | release/v1.0.4向けPRも解析・テスト対象にし、両エントリーポイントをコンパイル | 開発側だけでなく本番側のDart/API互換性も継続確認する |

既存の `MyApp` / `appRouter` はエントリーポイントから再exportし、import元の互換性を維持する。
Google Sign-Inの初期化呼び出し、Firebase初期化、通知初期化の順序も維持する。

## 意図的に維持した挙動

- 日付未設定のイベントは新しい順・古い順のどちらも末尾。同日の比較は時刻ではなくID。
- 公式イベントの初回読み込みはタグのorder順、バックグラウンド更新はtagIds順。
- 参照IDが重複した場合、公式イベントは最後の参照、自作イベントは最初の参照を使用。
- 見つからないタグは除外し、会場・グループは空モデルへフォールバック。
- 新規イベント登録時のタグ欠損エラーは変更しない。
- キーワードは大文字小文字を区別しないOR検索。空白のみの検索は0件。
- 通知は今日以降のイベントが対象。中止イベントも既存通知のキャンセル対象に含める。
- 通知対象は参加イベント、シリーズ順、元のイベント順を維持し、同一値のイベントを重複排除。
- 通知タイトル・スケジュール時刻・設定保存タイミング・useEffectの依存キーは変更しない。

仕様変更を混ぜないため、次の既存の境界挙動も残している。修正する場合は別途相談する。

- 公式／自作の両表示フラグを有効にすると積集合となり0件。両方無効では元の一覧へ戻る。
- マイイベントの空のtargetListは現在のallEventsへフォールバックする。
- 参加済み除外の既存条件は今回変更しない。
- 通知の参加種別未設定は全参加通知に含まれる。参加登録済みの「不参加」は未登録向け通知には含めない。

## 回帰テスト

- 起動フェーズの順序・前段完了待ち・失敗時の停止・再読み込みでの重複取得防止。
- 結合時の欠損／重複参照、タグ順、入力を変更しないこと。
- 日付とIDのソート、期間の境界、タグ・キーワードの組み合わせ、表示フラグ全8通り。
- 3画面の共通フィルタ適用とキーワード更新。
- 通知の有効／無効、参加種別、チェックインID、中止・過去・日付未設定、9シリーズの各フラグ、重複排除と順序。
- 既存のFirestore取得回数、初回ログインの参加情報更新、操作フィードバックのテストも継続する。

## 検証上の区別

CIの `flutter build bundle --release` はDartとassetsのコンパイル確認であり、APKの署名・ネイティブビルド成功を意味しない。
実機でのログイン・通知配信・起動確認と、署名環境での以下のビルドはリリース前に確認する。

```sh
flutter analyze --no-pub
flutter test --no-pub --reporter expanded
flutter build apk --release --no-pub --flavor prod -t lib/main.dart
flutter build apk --release --no-pub --flavor dev -t lib/main_dev.dart
```
